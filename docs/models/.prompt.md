# docs/models/ 目录说明

本目录存放各**模块的架构与设计文档**。在编辑或新增本目录下文档时，请遵守以下约定。

---

## 1. 文档定位

- **仅记录架构与设计**，不记录代码实现细节（不写具体代码示例、不贴实现代码）。
- 结论与接口层面的描述（如 API 列表、职责划分、协作关系）保留；实现细节放到 Unity 工程或代码注释中。

---

## 2. 验收标准

- **每个模块文档必须包含「验收标准」小节**，明确该模块通过验收的判定条件。
- **总验收关系**：当五个模块文档中的验收标准**全部**满足后，即可按照 [README 中的「工作流程」](../../README.md#工作流程) 进行端到端总验收（唤起 → 输入 → 处理 → 展示 → 选择 → 输出）。
- 各文档末尾可附带一句总验收说明，指向 README 工作流程。

---

## 3. 验收流程

各模块文档除「验收标准」外，须包含 **「验收流程」** 小节，并与实现约定一致：**通过日志 + 人工观察** 完成验收。

### 3.1 用户验收时的两部分

用户按文档完成操作后，验收分为两部分，缺一不可：

1. **人工观察**：按文档中的观察要点，用眼睛确认界面与表现（是否显示、位置/尺寸、交互反馈、内容等）。
2. **读 Log 验收**：打开当次运行的 Log，根据文档中的 **Log 验收清单** 逐项核对：清单中的每条是否在 Log 中有对应输出且含义/取值符合预期；在清单上逐项打勾或标注是否通过。清单全部通过且无遗漏项，则 Log 部分验收通过。

### 3.2 文档侧：验收流程小节怎么写

- 每个模块文档的 **「验收流程」** 小节中，**必须**提供 **「Log 验收清单」**，**逐条列出**当用户按该小节的操作步骤执行后**应在 Log 中出现的全部验收点**（例如：某函数被调用、某参数/返回值为某值、某状态为某值等）。该清单是「Log 里会出现哪些待验证输出」的**唯一约定**：文档先定清单（列出全部需在 Log 中出现的验收点），实现按清单在代码里打 Log，用户按操作步骤执行后做观察验收并按清单读 Log 打勾，避免遗漏。清单中每条应可判定，并与「验收标准」中需通过 Log 验证的条目对应。
- **按步骤指导用户应如何操作**（例如：启动场景、点击某处、输入某内容、切换某模式等），说明操作顺序与前提条件（如「先启动 SteamVR」「先打开某场景」），使用户按顺序操作后能触发 Log 验收清单中的全部输出。
- 写明**人工观察**要点（「观察……」「确认……」），与「Log 验收清单」一起构成完整验收流程。

### 3.3 实现侧：按清单打 Log

- **对照该模块文档中的 Log 验收清单**，在相关函数或流程中写入 Log（如 Unity `Debug.Log` 等），使清单中每一项在用户按文档操作后都会产生对应输出。
- 建议使用统一前缀（如 `[VRCPinYin.验收]`）或标签，便于在 Console 中筛选。
- 实现完成后自测：按文档操作一遍，检查 Log 中是否覆盖清单全部条目，若有遗漏则补打 Log 或补清单。
